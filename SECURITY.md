# Security policy

## Supported versions

Only the latest revision on `main` is considered for fixes. Testnet deployments,
release candidates, and example configuration are not a statement that the
contracts have completed an independent production audit.

## Reporting a vulnerability

Please use GitHub's private **Security → Report a vulnerability** flow. Do not
open a public issue for an undisclosed vulnerability. If private reporting is
not available, contact the repository owners through an established private
channel before sharing technical details.

Never include wallet seed phrases, private keys, production proving material, or
unredacted sensitive transaction data in a report.

Include the affected revision, impact, reproduction steps, and a minimal proof
of concept where possible. Maintainers will acknowledge receipt, coordinate a
fix and disclosure timeline, and credit reporters who wish to be named.
